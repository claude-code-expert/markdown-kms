# 네이버 검색엔진 등록 가이드 (서치어드바이저)

`mingleup.net`을 네이버 검색에 노출시키는 절차. 코드 쪽(robots.txt·sitemap.xml·소유확인 태그)은 이미 들어가 있으므로, 이 문서는 **콘솔에서 사람이 해야 하는 일**을 순서대로 다룬다.

관련 문서: 구글 등록은 `search-console.md`(사이트맵·robots 설계 근거가 거기 있다), 배포·도메인은 `connect.md`.

---

## 요약

| 항목 | 값 |
|---|---|
| 콘솔 | [searchadvisor.naver.com](https://searchadvisor.naver.com) → **웹마스터 도구** |
| 등록 URL | **`https://www.mingleup.net`** (apex 아님) |
| 소유확인 | **HTML 태그** — `NAVER_SITE_VERIFICATION` env |
| 사이트맵 | `https://www.mingleup.net/sitemap.xml` |
| 추가 환경변수 | `NAVER_SITE_VERIFICATION` **1개** |

**구글과 가장 다른 점: 네이버에는 DNS 확인 방식이 없다.** HTML 태그(또는 HTML 파일 업로드)뿐이라 env를 넣고 재배포하는 과정이 반드시 필요하다.

또 하나 — 네이버는 **도메인 속성 같은 개념이 없다.** `www`와 apex가 별개 사이트로 취급되고, 둘 다 등록하는 것은 권장되지 않는다. 우리는 apex가 `www`로 308 리다이렉트되므로 **`www` 하나만** 등록한다.

---

## 0단계 — env 준비 (선행)

소유확인 코드는 1단계에서 받지만, **넣는 곳을 먼저 알아두면 왕복이 준다.** 코드를 받으면 아래에 넣고 재배포한다.

```
NAVER_SITE_VERIFICATION=<서치어드바이저가 준 content 값>
```

`.env.local`(로컬)과 Vercel **Production** 양쪽. env가 없으면 태그 자체가 나가지 않으므로, 넣기 전에는 소유확인이 절대 통과하지 않는다.

---

## 1단계 — 사이트 등록

**위치**: [searchadvisor.naver.com](https://searchadvisor.naver.com) 로그인 → 상단 **웹마스터 도구** → 사이트 등록

입력란에 프로토콜까지 포함한 전체 주소를 넣는다.

```
https://www.mingleup.net
```

> **함정 ①** — **apex(`https://mingleup.net`)를 넣지 않는다.** 네이버는 구글의 도메인 속성 같은 통합 개념이 없어 `www` 유무가 별개 사이트다. apex는 `www`로 308 리다이렉트되므로 등록해도 리다이렉트만 확인되고 실제 수집은 안 된다. 둘 다 등록하는 것도 네이버가 권장하지 않는다.

---

## 2단계 — 소유확인 (HTML 태그)

등록하면 소유확인 화면이 뜬다. **HTML 태그**를 고르면 이런 코드를 준다.

```html
<meta name="naver-site-verification" content="abc123def456..." />
```

**`content` 값만** 떼어 env에 넣는다. 태그 전체를 넣으면 안 된다.

```
NAVER_SITE_VERIFICATION=abc123def456...
```

`.env.local`과 Vercel Production 양쪽에 넣고 **재배포**한다. 배포가 끝난 뒤 실제로 태그가 나가는지 확인하고 나서 "소유확인" 버튼을 누른다.

```bash
curl -s https://www.mingleup.net/ | grep naver-site-verification
```

이 명령이 아무것도 출력하지 않으면 아직 누르면 안 된다 — env 누락이거나 재배포가 안 된 것이다.

> **함정 ②** — **env 추가만으로는 반영되지 않는다.** Vercel은 새 배포에만 env를 싣는다(`connect.md` §반복해서 밟는 함정 2). 재배포 없이 소유확인을 누르면 실패한다.

> **함정 ③** — 태그가 정상인데도 바로 실패할 수 있다. 네이버는 반영까지 시간이 걸리는 경우가 있어 **몇 시간 뒤 재시도**하면 통과하기도 한다. 위 `curl`로 태그가 확인되면 코드 쪽은 더 볼 것이 없다.

---

## 3단계 — 사이트맵 제출

**위치**: 사이트 목록에서 등록한 URL 클릭 → 좌측 **요청 → 사이트맵 제출**

```
https://www.mingleup.net/sitemap.xml
```

사이트맵은 코드가 자동 생성하므로(`src/app/sitemap.ts`) 따로 관리할 파일이 없다. 구글에 제출한 것과 **같은 파일**이다.

```bash
curl -s -o /dev/null -w "%{http_code} %{content_type}\n" https://www.mingleup.net/sitemap.xml
```

`200 application/xml`이 나와야 한다. `text/html`이면 배포가 안 된 것이다.

### RSS는 제출하지 않는다

**요청 → RSS 제출** 메뉴가 있지만 이 사이트에는 넣을 것이 없다. RSS는 블로그·뉴스처럼 **주기적으로 늘어나는 공개 글**을 알리는 용도인데, 이 앱의 공개 페이지는 랜딩·가입·로그인 3개로 고정이고 나머지 문서는 전부 워크스페이스 멤버 전용이다. 사이트맵으로 충분하다.

---

## 4단계 — robots.txt 수집 요청

**위치**: 좌측 **검증 → robots.txt** → **수집요청** 버튼

네이버 크롤러가 우리 `robots.txt`를 읽어가게 만드는 단계다. 항목이 안 보이면 새로고침한다.

우리 `robots.txt`는 `User-Agent: *`로 시작하므로 네이버 크롤러(`Yeti`)도 그 규칙을 그대로 따른다. 별도 `Yeti` 블록을 두지 않은 이유는, robots.txt 규격상 크롤러는 **자기 이름과 정확히 일치하는 그룹이 있으면 `*` 그룹을 통째로 무시**하기 때문이다. 중복 선언은 관리 지점만 늘리고 한쪽만 고쳐지는 사고를 부른다.

---

## 5단계 — 수집 요청과 확인

**위치**: 좌측 **요청 → 웹 페이지 수집**

```
https://www.mingleup.net/
```

랜딩만 요청하면 된다. 나머지는 사이트맵으로 발견되게 둔다.

상단 **간단체크**(하루 10회)로 접속 상태·robots.txt·메타태그를 한 번에 점검할 수 있다.

검색 노출까지는 보통 **2주 안팎** 걸린다. 네이버는 자체 품질 기준으로 노출을 결정하므로 등록이 곧 노출을 보장하지 않는다.

확인은 네이버 검색창에 `site:mingleup.net`.

---

## 구글과 무엇이 다른가

한 번에 비교해두면 헷갈리지 않는다.

| | 구글 Search Console | 네이버 서치어드바이저 |
|---|---|---|
| 속성 개념 | 도메인 속성(모든 서브도메인 포함) | **없음** — `www`/apex가 별개 사이트 |
| 소유확인 | DNS TXT / HTML 태그 / 파일 / GA / GTM | **HTML 태그 / 파일만** |
| 등록 주소 | `mingleup.net` (프로토콜 없이) | `https://www.mingleup.net` (전체 URL) |
| 사이트맵 | 전체 URL | 전체 URL |
| 재배포 필요 | ✗ (DNS 방식이면) | **✓** (태그를 배포해야 함) |
| 크롤러 | `Googlebot` | `Yeti` |

---

## 반복해서 밟는 함정

1. **apex를 등록한다.** 네이버에는 도메인 통합 개념이 없다. `https://www.mingleup.net` 하나만 등록한다 (1단계 함정 ①).
2. **메타태그 전체를 env에 넣는다.** `content` 값만 넣는다 (2단계).
3. **env만 넣고 재배포를 안 한다.** 태그가 안 나가 소유확인이 실패한다. `curl`로 먼저 확인한다 (2단계 함정 ②).
4. **소유확인 실패를 코드 문제로 오해한다.** `curl`에 태그가 보이면 코드는 정상이고, 네이버 반영이 늦은 것일 수 있다 (2단계 함정 ③).
5. **사이트맵에 경로만 넣는다.** 전체 URL이다 — 구글 도메인 속성과 같은 이유다(`search-console.md` 3단계 함정 ④).
6. **RSS를 억지로 만든다.** 공개 콘텐츠가 고정 3페이지라 넣을 것이 없다 (3단계).
7. **등록하면 바로 노출된다고 생각한다.** 2주 안팎 걸리고, 네이버 품질 기준에 따라 노출 여부가 갈린다.

---

## 알려진 미해결 이슈

**공개 콘텐츠가 3페이지뿐이라 네이버 노출 여지가 특히 작다.** 네이버는 문서 수와 갱신 빈도를 크게 보는 편이라, 블로그나 공개 문서 공유 같은 콘텐츠가 생기기 전까지는 브랜드명 검색 정도로만 잡힐 가능성이 높다. 그때가 되면 `sitemap.ts`에 해당 문서를 더하고 RSS 제출도 함께 검토한다.

**OG 이미지가 없다.** 네이버 검색결과·블로그 인용에서 썸네일이 비어 보인다. `search-console.md`에 적어둔 것과 같은 항목으로, `src/app/opengraph-image.tsx` 추가로 해결된다.
