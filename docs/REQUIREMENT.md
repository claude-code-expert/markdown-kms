## 1. 개요

워크스페이스 기반의 마크다운 문서 작성·관리 웹 애플리케이션이다. 사용자는 워크스페이스 안에서 폴더 트리로 문서를 조직하고, 듀얼 뷰(에디터 + 실시간 미리보기)로 문서를 작성하며, 역할 기반 권한(RBAC)으로 협업한다.

마크다운 파싱·렌더링의 정합성 기준은 **CommonMark 0.31.2**를 따른다. 단, 아래 3개 문법은 CommonMark에 포함되지 않은 **GFM 확장**이므로 별도 확장 플러그인으로 구현해야 한다.

- Strikethrough(취소선)
- Task List(태스크 목록)
- Table(표)

### 1.1 용어

| 용어 | 정의 |
|------|------|
| 워크스페이스 | 문서·폴더·멤버를 담는 최상위 컨테이너. RBAC 적용 단위 |
| 기본 워크스페이스 | 모든 회원이 가입 시 자동으로 소속되는 워크스페이스 |
| 소프트 삭제 | 레코드를 물리 삭제하지 않고 삭제 플래그 처리 후 휴지통으로 이동 |
| 자동 저장 | 입력 중단 20초 후 서버에 저장하는 디바운스 저장 |
| 임시 저장 | 내용 소실 방지를 위한 1분 주기 스냅샷 저장 |

## 2. 화면 구조

```
+------------------+---------------------------------------------+
|                  |  툴바 (lucide 아이콘)                        |
|  좌측 사이드바     +----------------------+----------------------+
|  (폴더 트리)      |                      |                      |
|                  |   마크다운 에디터      |   미리보기            |
|  워크스페이스      |                      |   (렌더링 결과)       |
|   └ 폴더          |                      |                      |
|      └ 자식 폴더   |                      |                      |
|         └ 문서    |                      |                      |
+------------------+----------------------+----------------------+
|  하단 상태 바 — 저장 상태 표시 (저장 중 / 저장됨 / 저장 실패)       |
+----------------------------------------------------------------+
```

- 좌측 사이드바: 워크스페이스 > 폴더 > 자식 폴더 > 문서의 트리를 표시한다.
- 우측 컨텐츠 영역: 좌측은 마크다운 에디터, 우측은 미리보기다.
- 하단 상태 바: 자동 저장 상태를 표시한다.

## 3. 기능 요구사항 (FR)

우선순위: **P0**(핵심, 없으면 제품 불성립) / **P1**(v1 필수) / **P2**(v1 포함하되 후순위 구현).

### 3.1 에디터 — FR-E

| ID | 요구사항 | 우선순위 |
|----|----------|:---:|
| FR-E1 | 제목 서식을 지원한다: H1~H4, P(일반 텍스트). CommonMark ATX heading(`#`~`####`) 기준으로 변환한다 | P0 |
| FR-E2 | 인라인 서식을 지원한다: Bold(`**`), Italic(`*`), Strikethrough(`~~`, GFM), Inline Code(`` ` ``) | P0 |
| FR-E3 | 목록을 지원한다: Bullet(`-`), Ordered(`1.`), Task(`- [ ]`, GFM) | P0 |
| FR-E4 | 블록 요소를 지원한다: Blockquote(`>`), Code Block(fenced ``` + 언어 info string), HR(`---`) | P0 |
| FR-E5 | 삽입 요소를 지원한다: Link(`[텍스트](url)`), Image(`![alt](url)`), Table(GFM) | P0 |
| FR-E6 | 이미지 업로드를 지원한다. 업로드 완료 시 에디터 커서 위치에 이미지 마크다운이 삽입된다 | P1 |
| FR-E7 | 툴바 아이콘은 **lucide** 아이콘을 사용한다. 클릭 시 클릭 시각화 효과(pressed 상태)를 표시하고, 마우스 오버 시 기능 설명 툴팁을 표시한다 | P1 |
| FR-E8 | 에디터 입력 후 **60ms 이내** 우측 미리보기에 렌더링 결과가 반영된다 | P0 |
| FR-E9 | 자동 저장: 입력 중단 후 **20초 디바운스**로 서버에 저장하고, 저장 상태(저장 중/저장됨/실패)를 하단 상태 바에 표시한다 | P0 |
| FR-E10 | 임시 저장: 입력이 발생한 문서는 **1분 간격**으로 임시 스냅샷을 저장하여 브라우저 크래시·네트워크 단절 시 내용 소실을 방지한다. 재진입 시 임시본이 서버 저장본보다 최신이면 복구 여부를 묻는다 | P1 |
| FR-E11 | 뷰 기능을 제공한다: Theme(라이트/다크), Layout(split/에디터 전용/미리보기 전용), Settings | P1 |

### 3.2 폴더 트리 — FR-T

| ID | 요구사항 | 우선순위 |
|----|----------|:---:|
| FR-T1 | 트리 구조는 워크스페이스 > 폴더 > 자식 폴더 > 문서 계층을 따른다 | P0 |
| FR-T2 | 중첩 폴더 구조는 **Closure Table** 패턴으로 저장한다. 조상-자손 관계 조회는 단일 쿼리로 수행 가능해야 한다 | P0 |
| FR-T3 | 폴더 생성·이름 변경·이동·삭제를 지원한다. 폴더 삭제는 소프트 삭제이며 하위 문서 처리 정책은 §3.3을 따른다 | P0 |

### 3.3 문서 관리 — FR-D

| ID | 요구사항 | 우선순위 |
|----|----------|:---:|
| FR-D1 | 문서 생성·수정·삭제를 지원한다. 삭제는 소프트 삭제(`is_deleted` + `deleted_at`)이며 즉시 휴지통으로 이동한다 | P0 |
| FR-D2 | 휴지통에서 문서를 복원하거나 **완전 삭제**(물리 삭제)할 수 있다 | P0 |
| FR-D3 | 문서마다 태그를 **최대 3개**까지 입력할 수 있다 | P1 |
| FR-D4 | 검색 기능으로 문서를 찾을 수 있다. 검색 대상: 문서 제목, 본문, 태그 | P1 |

### 3.4 Export — FR-X

| ID | 요구사항 | 우선순위 |
|----|----------|:---:|
| FR-X1 | 문서 단위 export: 단일 문서를 `.md` 파일로 다운로드한다 | P1 |
| FR-X2 | 폴더 단위 export: 폴더 하위의 문서 전체(자식 폴더 포함)를 폴더 구조 그대로 **zip으로 압축**하여 다운로드한다 | P1 |

### 3.5 프레젠테이션 — FR-P

| ID | 요구사항 | 우선순위 |
|----|----------|:---:|
| FR-P1 | 문서 에디터에서 전체화면 프레젠테이션 모드로 진입할 수 있다 | P2 |
| FR-P2 | 프레젠테이션 모드는 **TOC(제목 기반 목차) 섹션 내비게이션**을 지원한다. 이전/다음 섹션 이동과 목차에서 특정 섹션으로 바로 이동이 가능하다 | P2 |

### 3.6 워크스페이스·RBAC — FR-W

| ID | 요구사항 | 우선순위 |
|----|----------|:---:|
| FR-W1 | 워크스페이스는 역할 기반 접근 제어(RBAC)를 적용한다. 역할은 Owner / Admin / Editor / Viewer 4단계다 | P0 |
| FR-W2 | 권한 매트릭스는 아래 표를 따른다. 권한 없는 요청은 서버에서 403으로 거부한다 | P0 |
| FR-W3 | 회원은 워크스페이스에 가입 신청할 수 있다 | P1 |
| FR-W4 | Owner·Admin은 가입 신청을 승인하거나 거절할 수 있다 | P1 |
| FR-W5 | Owner·Admin은 회원을 검색하여 초대 메일(가입 링크)을 발송할 수 있다. 수신자가 링크를 클릭하면 자동으로 해당 워크스페이스 멤버로 처리된다 | P1 |

**권한 매트릭스 (FR-W2)**

| 역할 | 읽기 | 문서 작성 | 멤버 초대 | 설정 변경 | 삭제 | 가입 승인 |
|------|:----:|:--------:|:--------:|:--------:|:----:|:--------:|
| Owner | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| Admin | ✅ | ✅ | ✅ | ✅ | ❌ | ✅ |
| Editor | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ |
| Viewer | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ |

### 3.7 회원·인증 — FR-A

| ID | 요구사항 | 우선순위 |
|----|----------|:---:|
| FR-A1 | 1단계: 로그인 폼 기반 회원 가입·로그인을 제공한다 (이메일 + 비밀번호) | P0 |
| FR-A2 | 2단계: Google OAuth 로그인을 지원한다. 1단계 구현 시 OAuth 확장이 가능한 인증 구조로 설계한다 | P2 |
| FR-A3 | 모든 회원은 가입 완료 시 **기본 워크스페이스**에 자동 가입된다 | P0 |

## 4. 비기능 요구사항 (NFR)

### NFR-1. 성능

- NFR-1.1: 에디터 입력 → 미리보기 반영 지연은 **p95 기준 60ms 이내**여야 한다. 측정 방법: 10,000자 문서에서 keystroke 이벤트 → 미리보기 DOM 갱신 완료까지.
- NFR-1.2: 자동 저장 디바운스는 20초로 고정하며, 저장 요청 중 추가 입력이 발생하면 이전 요청을 취소하지 않고 최신 내용으로 후속 저장한다.
- NFR-1.3: 폴더 트리 조회는 Closure Table 기반 단일 쿼리로 수행한다. 트리 깊이에 비례해 쿼리 수가 늘어나는 재귀 조회(N+1)를 금지한다.

### NFR-2. 데이터 보존

- NFR-2.1: 임시 저장 스냅샷은 1분 주기로 생성하며, 문서당 최신 1개만 유지한다.
- NFR-2.2: 소프트 삭제된 문서·폴더는 활성 목록 조회에서 제외한다. 활성 조회 성능 확보를 위해 `is_deleted = false` 조건의 부분 인덱스를 사용한다.

### NFR-3. 보안

- NFR-3.1: 미리보기 렌더링 결과는 반드시 sanitize를 거친다. CommonMark의 raw HTML 블록·인라인 HTML은 sanitize 미통과 시 렌더링하지 않는다 (XSS 방어).
- NFR-3.2: 모든 권한 검증은 클라이언트가 아닌 서버에서 수행한다. UI에서 버튼을 숨기는 것은 권한 제어로 인정하지 않는다.
- NFR-3.3: 초대 링크는 서명된 일회성 토큰을 사용하고 유효 기간을 갖는다.

### NFR-4. UX

- NFR-4.1: 툴바 버튼은 hover 시 300ms 이내 툴팁을 표시하고, 클릭 시 시각적 피드백(pressed/active 상태)을 즉시 표시한다.
- NFR-4.2: 저장 상태는 하단 상태 바에 항상 표시한다. 저장 실패 시 사용자에게 재시도 수단을 제공한다.

### NFR-5. 정합성

- NFR-5.1: 마크다운 파싱은 CommonMark 0.31.2 스펙 예제 테스트(spec_tests)를 기준으로 검증한다. GFM 확장(취소선·태스크·표)은 확장 테스트를 별도 작성한다.
- NFR-5.2: 문서 export(.md)는 에디터에 입력된 원본 마크다운을 무손실로 출력한다.

## 5. 사용자 스토리 (US)

각 스토리의 인수 조건은 측정·검증 가능한 문장만 사용한다.

### US-1. 문서 작성 (P0)

> 작성자(Editor 이상)로서, 에디터에 마크다운을 입력하면 즉시 결과를 확인하고 싶다. 문법 결과를 눈으로 검증하며 쓰기 위해서다.

**인수 조건**
- 에디터에 `## 제목`을 입력하면 60ms 이내 미리보기에 H2가 렌더링된다.
- 툴바에서 Bold 버튼을 클릭하면 선택 텍스트가 `**텍스트**`로 감싸진다.
- H1~H4, Bold/Italic/Strikethrough/Inline Code, Bullet/Ordered/Task, Blockquote/CodeBlock/HR, Link/Image/Table 각각의 툴바 버튼이 동작한다.

### US-2. 자동 저장 (P0)

> 작성자로서, 저장 버튼을 누르지 않아도 내용이 보존되기를 원한다. 작업 내용을 잃지 않기 위해서다.

**인수 조건**
- 입력 중단 1초 후 서버 저장 요청이 발생하고 하단 상태 바가 "저장 중 → 저장됨"으로 전환된다.
- 입력 후 1분이 지나면 임시 스냅샷이 존재한다.
- 저장되지 않은 변경이 있는 상태에서 브라우저를 강제 종료 후 재진입하면 복구 여부를 묻는 안내가 표시된다.

### US-3. 문서 조직 (P0)

> 사용자로서, 워크스페이스 아래 폴더와 자식 폴더로 문서를 정리하고 싶다.

**인수 조건**
- 폴더 안에 자식 폴더를 생성할 수 있고, 트리에 계층이 표시된다.
- 특정 폴더의 전체 하위 항목 조회가 단일 쿼리로 수행된다 (Closure Table).

### US-4. 삭제와 복원 (P0)

> 사용자로서, 실수로 지운 문서를 되살리고 싶다.

**인수 조건**
- 문서 삭제 시 목록에서 사라지고 휴지통에 나타난다.
- 휴지통에서 복원하면 원래 폴더 위치에 다시 나타난다.
- 휴지통에서 완전 삭제하면 어떤 조회로도 노출되지 않는다.

### US-5. 워크스페이스 협업 (P0~P1)

> Owner로서, 팀원에게 역할에 맞는 권한만 부여하고 싶다.

**인수 조건**
- Viewer 계정으로 문서 작성 API를 호출하면 403이 반환된다.
- Admin은 워크스페이스를 삭제할 수 없고, Owner만 삭제할 수 있다.
- 가입 신청이 접수되면 Owner·Admin에게 승인 대기 목록이 표시되고, 승인 시 신청자가 멤버가 된다.
- 초대 메일의 가입 링크를 클릭한 사용자는 추가 절차 없이 해당 워크스페이스 멤버가 된다.

### US-6. 검색과 태그 (P1)

> 사용자로서, 태그와 키워드로 문서를 빨리 찾고 싶다.

**인수 조건**
- 문서에 태그를 3개까지 입력할 수 있고, 4개째 입력은 거부된다.
- 검색어가 제목·본문·태그 중 하나와 일치하면 결과에 나타난다.

### US-7. Export (P1)

> 사용자로서, 문서를 외부로 가져가고 싶다.

**인수 조건**
- 문서 export 시 원본과 동일한 내용의 `.md` 파일이 다운로드된다.
- 폴더 export 시 폴더 구조가 유지된 `.zip` 파일이 다운로드된다.

### US-8. 프레젠테이션 (P2)

> 발표자로서, 작성한 문서를 그대로 발표 자료로 쓰고 싶다.

**인수 조건**
- 에디터에서 프레젠테이션 버튼 클릭 시 전체화면으로 전환된다.
- TOC가 표시되고, 목차 항목 클릭 시 해당 섹션으로 이동한다.
- 키보드(←/→ 또는 PgUp/PgDn)로 이전·다음 섹션으로 이동한다.

### US-9. 가입 (P0, OAuth는 P2)

> 신규 사용자로서, 간단히 가입하고 바로 문서를 쓰고 싶다.

**인수 조건**
- 이메일·비밀번호로 가입하면 즉시 로그인되고 기본 워크스페이스가 사이드바에 표시된다.
- (2단계) Google 계정으로 로그인하면 동일하게 기본 워크스페이스에 소속된다.

## 6. 데이터 모델 지침

구현 시 최소한 아래 제약을 반영한다. 상세 스키마는 TRD에서 확정한다.

- `folder_closure(ancestor_id, descendant_id, depth)`: 폴더 계층 Closure Table. self-reference(depth=0) 포함.
- `document.is_deleted`, `document.deleted_at`: 소프트 삭제. `folder`도 동일.
- `document_tag`: 문서당 최대 3행 제약 (애플리케이션 레벨 검증 + 저장 시 검증).
- `workspace_member(workspace_id, user_id, role)`: role ∈ {OWNER, ADMIN, EDITOR, VIEWER}.
- `workspace_join_request`: 가입 신청 상태(PENDING/APPROVED/REJECTED).
- `invitation(token, workspace_id, expires_at, used_at)`: 초대 링크.
- `document_draft`: 1분 주기 임시 스냅샷 (문서당 1행 upsert).

## 7. 범위 제외

아래 항목은 본 명세의 범위가 아니다. 요구 시 별도 버전에서 다룬다.
