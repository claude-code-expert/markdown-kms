# 제품 개요와 재디자인 범위

## 한 줄 정의

워크스페이스 안에서 폴더 트리로 문서를 조직하고, 에디터·미리보기 듀얼 뷰로 마크다운을 쓰며, 4단계 역할(Owner/Admin/Editor/Viewer)로 협업하는 웹 앱. 실시간 동시 편집(CRDT)·댓글·버전 히스토리는 스코프 밖이다.

## 스택 (변경 대상 아님)

Next.js 15 App Router + TypeScript, PostgreSQL 16 + Drizzle ORM, Auth.js v5, CodeMirror 6(에디터), unified/remark-gfm/rehype-sanitize(마크다운 파이프라인), CSS Modules(스타일링 — Tailwind나 CSS-in-JS로 바꾸는 건 이 재디자인의 스코프가 아니면 언급 필요). 패키지 매니저 pnpm.

## 재디자인의 목표

지금 UI는 여러 세션에 걸쳐 기능 단위로 점진적으로 만들어져 화면마다 디자인 완성도가 고르지 않다(예: 대시보드는 세로 리스트인데 랜딩은 그리드, 배지 스타일이 화면마다 미묘하게 다름). 목표는 **전체 사이트를 하나의 일관된 디자인 시스템으로 개편**하는 것 — 색상·타이포·간격·모션·아이콘 세트를 처음부터 다시 설계하고, 모든 화면과 컴포넌트에 동일한 규칙을 적용한다.

## 건드려도 되는 것 (전부 자유)

- 색상 팔레트 전체(라이트/다크 둘 다), accent 색상 포함
- 타이포그래피(폰트 패밀리·크기 스케일·굵기)
- spacing/radius/motion 토큰 값
- 아이콘 세트(지금은 lucide-react — 다른 아이콘 라이브러리로 바꿔도 됨, 다만 실제 사용 가능한 npm 패키지여야 함)
- 레이아웃 비율·컴포넌트 배치(사이드바 폭, 카드 그리드 vs 리스트, 버튼 위치 등)
- 각 컴포넌트의 시각적 스타일(그림자·테두리·radius·hover 효과)

## 유지해야 하는 것 (기능 계약 — 03·04·05 문서에 전부 표시됨)

새 디자인이 이 목록을 깨면 실제 동작이 바뀌거나 기존 서버 API·테스트와 어긋난다. **디자인(생김새)은 자유지만, 아래 목록의 "무엇이 존재하는가/언제 나타나는가"는 유지해야 한다:**

1. **권한에 따라 버튼이 사라지거나 disabled되는 지점** — 예: Viewer는 저장/삭제 버튼 자체가 없음, 완전 삭제는 Admin 이상만, 워크스페이스 삭제는 Owner만. 서버가 계산해서 내려주는 boolean이라 UI가 임의로 다 보여줄 수 없다.
2. **상태별로 다른 UI가 필요한 지점** — 새 문서(저장만)/조회 중 문서(수정+삭제), 검색 결과 없음, 로딩, 에러+재시도, disabled+힌트문구(숨김이 아니라 "왜 안 되는지" 텍스트로 안내).
3. **확인 다이얼로그가 필요한 파괴적 액션** — 폴더/문서 삭제, 워크스페이스 삭제(이름 재입력 확인), 완전 삭제, 가입 신청 거절.
4. **폼 필드와 유효성 검증 지점** — 태그 3개 제한, 워크스페이스 이름 100자 제한 등. 클라이언트 UI에 반드시 반영돼야 함(서버도 별도로 검증하지만 UX상 필요).
5. **에디터 툴바의 서식 기능 13종 + 3가지 레이아웃 모드(분할/에디터만/미리보기만)** — 버튼 개수·기능은 고정, 아이콘·배치·스타일은 자유.
6. **사이드바의 기능**(리사이즈, 접기/펼치기, 드래그앤드롭으로 폴더/문서 이동, 우클릭 컨텍스트 메뉴) — 존재해야 하는 기능이지 특정 픽셀값이 아님.
