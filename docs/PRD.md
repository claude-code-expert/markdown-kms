REQUIREMENT.md의 FR/NFR/US 정의는 이 문서에서 반복하지 않는다. 여기 없는 내용은 REQUIREMENT를 따르고, 두 문서가 충돌하면 **이 문서가 우선**한다 (충돌 지점은 전부 §2에 있다).

---

## 1. 제품 한 줄 정의

워크스페이스 안에서 폴더 트리로 문서를 조직하고, 에디터·미리보기 듀얼 뷰로 마크다운을 쓰며, 4단계 역할(Owner/Admin/Editor/Viewer)로 협업하는 웹 앱. 파싱 정합성 기준은 CommonMark 0.31.2 + GFM 확장 3종(취소선·태스크·표)뿐이다. 그 외 GFM 문법(각주, autolink 등)은 지원하지 않는다.

## 3. 역할과 권한 (확정판)

REQUIREMENT의 매트릭스에 §2에서 확정한 행을 더한 최종 매트릭스. 서버가 이 표대로 검증하고, 위반은 403이다 (NFR-3.2).

| 동작 | Owner | Admin | Editor | Viewer |
|------|:---:|:---:|:---:|:---:|
| 문서·폴더 읽기, 검색, export | ✅ | ✅ | ✅ | ✅ |
| 문서 작성·수정, 폴더 생성·이동·이름변경 | ✅ | ✅ | ✅ | ❌ |
| 문서·폴더 소프트 삭제, 휴지통 복원 | ✅ | ✅ | ✅ | ❌ |
| 휴지통 완전 삭제 | ✅ | ✅ | ❌ | ❌ |
| 멤버 초대, 가입 승인·거절 | ✅ | ✅ | ❌ | ❌ |
| 워크스페이스 설정 변경 | ✅ | ✅ | ❌ | ❌ |
| 워크스페이스 삭제 | ✅ | ❌ | ❌ | ❌ |

워크스페이스 생성은 역할과 무관하게 모든 회원이 가능하다 (§2-1). 기본 워크스페이스는 시스템이 시드하며 삭제 불가, 전 회원 EDITOR 자동 가입.

> **개정 (2026-08-02, 제품 오너 결정 — D-15 override):** 위 매트릭스의 "워크스페이스 삭제"(Owner 전용)는 하드 영구 삭제가 아니라 **소프트 삭제**(`workspace.is_deleted=true`)로 확정한다. 삭제 시 워크스페이스 행과 멤버십은 보존되고 활성 목록에서만 사라지며, 복원 UI는 Phase 4 휴지통과 함께 도입한다. Owner 전용 · 기본 워크스페이스 삭제 불가는 유지. 이는 문서·폴더 소프트 삭제(Editor 이상)와 별개인 워크스페이스 레벨 삭제의 의미를 하드→소프트로 개정한 것이다(TRD §3 `is_deleted` 컬럼 추가).

## 4. 릴리스 단위

우선순위(P0/P1/P2)를 그대로 릴리스 경계로 쓴다. 각 단계는 이전 단계 완료를 전제한다.

**R1 — P0 (제품 성립선).** 이것만 있으면 혼자 쓰는 문서 도구로 완결된다.
- 이메일 가입·로그인, 기본 워크스페이스 자동 가입 (FR-A1, A3)
- 3분할 화면: 트리 사이드바 + 에디터 + 미리보기 + 하단 저장 상태 바 (§2 화면 구조)
- 에디터 서식 전부(FR-E1~E5)와 60ms 미리보기(FR-E8), 1초 디바운스 자동 저장(FR-E9)
- 폴더 트리 CRUD, Closure Table 저장 (FR-T1~T3)
- 문서 CRUD, 휴지통 복원·완전 삭제 (FR-D1, D2)
- RBAC 4역할 + 서버 403 (FR-W1, W2) — 워크스페이스 생성 포함 (§2-1)

**R2 — P1 (협업·보존).**
- 이미지 업로드(FR-E6), 툴바 lucide·툴팁·pressed(FR-E7), 임시 저장·크래시 복구(FR-E10), 테마·레이아웃 전환(FR-E11)
- 태그 최대 3개(FR-D3), 제목·본문·태그 검색(FR-D4)
- 문서 .md export, 폴더 .zip export (FR-X1, X2)
- 가입 신청·승인, 회원 검색·초대 메일 (FR-W3~W5)

**R3 — P2.**
- 프레젠테이션 모드 + TOC 내비게이션 (FR-P1, P2)
- Google OAuth (FR-A2) — R1의 인증 구조가 provider 추가만으로 확장되는지가 인수 기준

## 5. 인수 기준 보강

REQUIREMENT §5의 US 인수 조건에 다음을 추가한다. 전부 측정 가능 문장이다.

- **미리보기 성능**: 10,000자 문서에서 keystroke → 미리보기 DOM 갱신 p95 ≤ 60ms (NFR-1.1). 측정은 자동화 테스트로 수행하고 수치를 리포트에 남긴다.
- **저장 순서 보장**: 의도적 네트워크 지연(옛 요청이 늦게 도착)을 재현해도 최종 저장본은 마지막 입력 내용이다 (§2-8).
- **폴더 삭제 cascade**: 문서 3개·자식 폴더 1개를 가진 폴더를 삭제하면 4개 항목 모두 활성 목록에서 사라지고, 휴지통에는 폴더 1건만 표시되며, 복원 시 4개가 원위치로 돌아온다 (§2-2).
- **sanitize**: `<script>alert(1)</script>`를 본문에 입력해도 미리보기에서 스크립트가 실행되지 않는다 (NFR-3.1).
- **태그 상한**: 4번째 태그 입력은 클라이언트에서 거부되고, API 직접 호출도 서버가 거부한다 (US-6 + NFR-3.2 원칙).
- **초대 토큰**: 사용된 링크 재클릭과 만료 링크 클릭은 모두 거부된다 (NFR-3.3).

## 6. 범위 제외

REQUIREMENT §7과 동일: 실시간 동시 편집(CRDT/OT), 댓글, 버전 히스토리, 위키 링크, 외부 공개 링크, 알림, 감사 로그. 여기에 하나를 명시적으로 추가한다.

- **다중 세션 동시 편집 충돌 해소 없음.** 같은 문서를 두 브라우저에서 열어 편집하면 나중 저장이 이긴다(last-write-wins). §2-8의 시퀀스 가드는 단일 세션의 순서 보장 장치이지 동시 편집 병합이 아니다.
