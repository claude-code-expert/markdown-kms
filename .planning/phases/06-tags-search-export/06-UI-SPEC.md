# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — shadcn 미도입 (Phase 1~5와 동일, `components.json` 부재로 재확인) |
| Preset | not applicable |
| Component library | none — 순수 CSS Modules + `src/app/globals.css`의 `docs/ui-kit.html` 이식 토큰. 이 phase는 새 팔레트를 만들지 않고 기존 라이트/다크(Phase 5) 토큰만 재사용한다 |
| Icon library | lucide-react (기존 설치, 추가 의존성 없음) |
| Font | IBM Plex Sans(UI 크롬 전부) — IBM Plex Mono는 `EditorHost` 소유, 이 phase가 건드리지 않음 |

**이 phase가 신규로 설계하는 표면:** 태그 chip 입력(메타 바, `DocumentWorkspace` 신규 행), 사이드바 상단 검색 입력 + 검색 결과 리스트(`FolderTree` 신규 표면), 문서/폴더 컨텍스트 메뉴의 export 항목 2종(기존 `FolderContextMenu` 배열에 항목 추가만, 컴포넌트 자체는 무변경).

**재사용 원칙(재질문 대상 아님):** `FolderContextMenu`/`Button`/`ConfirmDialog`의 기존 관례를 그대로 확장한다. 새 색상·새 컴포넌트 라이브러리·새 radius 값을 발명하지 않는다(태그 chip의 pill radius 1건만 이 phase가 처음 도입하는 값 — 아래 Spacing Exceptions에서 근거 명시). 다크 테마는 Phase 5가 이미 만든 `[data-theme="dark"]` 12개 변수 오버라이드만으로 전부 자동 전환되므로(전 컴포넌트 `var(--token)` 참조), 이 phase가 새로 만드는 표면도 전부 토큰만 참조해 별도 다크 CSS를 추가하지 않는다.

## Layout & Composition Contract

| 규칙 | 내용 |
|------|------|
| 태그 메타 바 위치 | `DocumentWorkspace`의 `titleRow`(40px, 하단 1px 구분선)와 `body`(`EditorPreviewLayout`) 사이에 새 행 삽입: `titleRow → tagBar(신규) → body → SaveStatusBar`. 04/05-UI-SPEC이 이미 "제목 행 아래 메타 바"로 자리를 예고해 둔 위치 그대로(06-CONTEXT.md 잠금) |
| 태그 메타 바 높이 | `min-height: 40px`(title row/status bar와 동일 리듬), 상하 padding 8px(sm) — chip 높이 24px + 상하 8px = 40px로 스케일에 정확히 맞아떨어진다(신규 예외 값 발명 없음). 하단 1px solid `var(--border)`(title row와 동일 관례로 body와 분리) |
| 검색 입력 위치 | `FolderTree`의 `.sidebar` 최상단, 기존 `.header`("폴더" 라벨 + 새 폴더/새 문서 버튼) **바로 위**에 새 행 추가: `searchBox(신규) → header → tree(또는 searchResults) → trashLink → ThemeToggle`. `.header`는 검색 중에도 그대로 유지(새 폴더/새 문서 버튼 비활성화 등 추가 조건 분기 없음 — 검색 중 폴더/문서 생성을 막을 이유가 없고, 그 편이 더 단순한 구현이다) |
| 검색 결과 리스트 위치 | `.tree`가 차지하던 `flex:1` 슬롯을 검색 활성 시(디바운스 후 쿼리 비어있지 않음) `.searchResults`로 교체. 둘 중 하나만 렌더(동시 렌더 없음) — 쿼리를 지우면 즉시 `.tree`로 복귀 |
| export 메뉴 항목 위치 | 기존 `FolderContextMenu` 배열에 항목만 추가(컴포넌트 무변경). 문서 메뉴(`docMenuItems`, 현재 "삭제" 1항목): ".md 내보내기"를 "삭제" **앞**에 삽입 → [.md 내보내기, 삭제]. 폴더 메뉴(`menuItems`, 현재 새 하위 폴더/이름 변경/이동.../삭제): ".zip 내보내기"를 "삭제" **앞**, "이동..." **다음**에 삽입 → [새 하위 폴더, 이름 변경, 이동..., .zip 내보내기, 삭제] — 파괴적 항목은 항상 배열 마지막이라는 기존 관례를 유지 |
| export 실패 배너 위치 | 사이드바 `.tree`(또는 `.searchResults`) 영역 상단, Phase 4 "복원-루트 안내 배너"와 동일한 슬롯·스타일을 재사용(신규 컴포넌트 없음, 색만 destructive로 교체) |
| 반응형 | 이 phase 범위 밖(Phase 1~5와 동일 — 데스크톱 폭 전제) |

## Spacing Scale

Phase 1~5와 동일 스케일 재사용, 신규 토큰 없음:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | 태그 아이콘-chip 사이 gap, chip 내부 텍스트-X 사이 gap, 검색 아이콘-입력 사이 gap |
| sm | 8px | 메타 바 상하 padding, chip 사이 gap, chip 좌우 padding, 검색 결과 행 상하 padding, 검색 입력 좌우 padding(헤더와 동일) |
| md | 16px | 메타 바 좌우 padding(제목 입력과 동일), 검색 결과 행 좌우 padding(휴지통 목록 행과 동일 관례) |
| lg | 24px | (이 phase 미사용) |
| xl | 32px | (이 phase 미사용) |
| 2xl | 48px | (이 phase 미사용) |
| 3xl | 64px | (이 phase 미사용) |

**Exceptions:** 태그 chip 높이 24px — 사이드바 헤더 버튼(Phase 3, 24×24px)과 동일한 기존 예외 값을 재사용(새 치수 발명 아님). chip border-radius **999px(완전한 pill)** — 이 phase가 처음 도입하는 유일한 신규 시각값. 근거: 기존 컴포넌트의 radius는 전부 "박스형"(Button 6px, Input 6px, ConfirmDialog 8px)이라 태그처럼 "다중 항목 나열형" UI에 그대로 쓰면 chip이 좁은 사각형이 되어 텍스트와 구분이 흐려진다 — 완전 pill은 chip류 UI의 표준 관례이며 다른 어떤 기존 요소와도 시각적으로 겹치지 않는다(재사용 가능한 기존 값이 없어 신규 도입, 발명 최소화 원칙에 부합). 검색 결과 태그(읽기 전용, 축소판) 높이 18px·폰트 11px — Phase 2 툴바 툴팁의 기존 11px 예외를 재사용(새 폰트 크기 발명 아님).

## Color

Phase 1~5가 이식/확정한 토큰 그대로 재사용(재정의 없음, 신규 색상 없음). 라이트/다크 두 값 모두 `[data-theme="dark"]` 오버라이드가 이미 처리하므로 아래는 라이트 기준 hex만 표기(다크는 05-UI-SPEC Color 섹션의 동일 토큰이 자동 적용):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff`(`--bg`) | 메타 바 배경, 검색 입력 배경, 사이드바 배경 — 변경 없음 |
| Secondary (30%) | `#f8fafc`/`#eef2f6`/`#e5e7eb`(`--surface`/`--surface-2`/`--border`) | 태그 chip 배경(`--surface-2`) + 테두리(`--border`), 검색 결과 행 hover(`--surface-2`), 메타 바/검색 입력 하단 구분선(`--border`) |
| Accent (10%) | `#2563eb`(`--accent`) | 아래 "Accent reserved for" 목록에 한정 |
| Destructive | `#dc2626`(`--destructive`) | 태그 저장 실패 텍스트, chip 제거(X) hover, export 실패 배너 |

**Accent reserved for (Phase 1~5 목록에 이 phase 항목만 추가):**
- (승계) 선택된 트리 노드, 열려있는 문서 노드, 유효 드롭 대상, 각종 focus 아웃라인, 레이아웃/테마 토글 활성 상태
- **[신규]** 태그 입력 focus 시 메타 바 하단 구분선(제목 입력 focus와 동일 관례 — 새 아웃라인 없이 기존 구분선 색만 전환)
- **[신규]** 검색 입력 focus 시 하단 구분선(동일 관례)
- **[신규]** 검색 결과 리스트가 로딩 중일 때 검색 아이콘 자리의 스피너 `border-top-color`(기존 `.spinner` 패턴 재사용, 신규 값 아님)

**Accent를 쓰지 않는 것(명시):** 태그 chip 자체(추가/제거는 매 상호작용마다 반복되는 일상 조작이라 accent로 강조하면 소란스럽다 — Phase 4 "저장 완료 무강조" 원칙과 동일 근거), export 메뉴 항목(다른 메뉴 항목과 동일한 중립 스타일 — 강조할 이유 없는 평범한 액션), 검색 결과 행 자체(hover만 `--surface-2`, 선택/활성 개념이 없는 단순 리스트라 accent 불필요).

## Tag Meta Bar Contract (DOC-03)

> 잠긴 값(06-CONTEXT.md, 재질문 아님): 제목 행 아래 메타 바, chip 스타일, Enter/comma 추가, X 제거, 3개 도달 시 입력 비활성, 서버가 최종 권위(PUT replace-all, COUNT>3 400). 아래는 이 값들의 **시각·상태 계약**만 다룬다.

| 요소 | 값 |
|------|-----|
| 레이아웃 | 한 줄 flex 행: [lucide `Tag` 14px `var(--muted)`] gap 4px(xs) [chip 0~3개, gap 8px(sm)] [bare 텍스트 입력, `flex:1 min-width:80px`] |
| chip 스타일 | 높이 24px, 배경 `var(--surface-2)`, 테두리 1px solid `var(--border)`, radius 999px, 좌우 padding 8px(sm), 내부 [텍스트] gap 4px(xs) [X 버튼 12px] |
| chip 텍스트 | Body(13/400) `var(--text)`, 최대 너비 120px 초과 시 ellipsis(overflow 대응, `title` 속성으로 전체 텍스트 hover 노출 — 네이티브 브라우저 툴팁, 별도 커스텀 컴포넌트 없음) |
| chip X 버튼 | lucide `X` 12px `var(--muted)`, 배경 없음, 클릭 즉시 제거(확인 다이얼로그 없음 — replace-all API라 언제든 재입력 가능한 가역적 조작) |
| chip-hover-remove | X 버튼에 마우스 hover 시에만 X 아이콘 색이 `var(--destructive)`로 전환(제거될 것임을 예고) — chip 전체가 아니라 X 버튼 자체에만 적용되는 상태 |
| 입력 — empty(0개 태그) | placeholder "태그 추가 (Enter로 추가)" |
| 입력 — typing(1~2개 태그, 텍스트 입력 중) | 별도 스타일 변화 없음, 값 그대로 표시 |
| 입력 — at-limit-disabled(3개 도달) | `disabled` 속성, `opacity: 0.5`, `cursor: not-allowed`, placeholder가 "최대 3개까지 추가할 수 있어요"(`var(--dim)`)로 교체 |
| 입력 — duplicate-rejected | 이미 존재하는 chip과 대소문자 무시 일치 시 Enter/comma가 새 chip을 만들지 않고 입력만 비움 + 메타 바 아래 에러 텍스트(Copywriting 참조, `FolderTreeNode.module.css` 기존 `.error` 클래스 재사용) 노출. 에러는 사용자가 입력을 다시 시작하는 순간(다음 keystroke) 사라진다 — 타이머 없음(불필요한 setTimeout 로직 추가 안 함) |
| 태그 추가/제거 → 서버 반영 | Enter/comma 또는 X 클릭 즉시 chip을 로컬에 반영(제목 입력과 동일한 "즉시 로컬 갱신 + 백그라운드 저장" 패턴 — 트리의 "서버 확정 후에만 반영" 원칙과는 다른 범주: 트리는 구조적 생성/삭제라 서버 ID가 필요하지만, 태그는 이미 확정된 문서에 대한 replace-all이라 즉시 반영이 자연스럽다) → `PUT /api/documents/:id/tags`로 전체 배열 전송 |
| 태그 저장 실패(tag save fail) | 방금의 로컬 변경(추가된 chip 제거 또는 제거된 chip 복원)을 되돌리고, 메타 바 아래 에러 텍스트 "태그를 저장하지 못했어요. 다시 시도해 주세요." 노출(같은 `.error` 클래스). 다음 성공한 태그 조작이 에러를 자동으로 지운다(별도 닫기 버튼·타이머 없음) |
| dark 테마 | 전부 `var(--token)` 참조라 Phase 5 오버라이드만으로 자동 전환, 이 phase가 추가하는 CSS 없음 |

## Search Contract (DOC-04)

> 잠긴 값(06-CONTEXT.md): 사이드바 상단, debounce ~300ms, 현 워크스페이스 범위, 결과=제목+본문 스니펫+태그, 클릭 시 문서로 이동, VIEWER+. 아래는 시각·상태 계약만 다룬다.

| 요소 | 값 |
|------|-----|
| 검색 입력 행 | 높이 40px, 하단 1px solid `var(--border)`, 좌우 padding 8px(sm) — 사이드바 헤더와 동일 리듬 |
| 아이콘(좌측) | lucide `Search` 16px `var(--muted)` — idle/typing 상태의 기본 아이콘 |
| placeholder | "문서 검색" |
| 지우기 버튼(우측) | 값이 비어있지 않을 때만 렌더, lucide `X` 14px `var(--muted)` hover `var(--text)` — 클릭 시 값 비우고 즉시 `.tree`로 복귀(확정된 요청이 있었다면 무시) |
| idle(쿼리 없음) | 좌측 아이콘 `Search`, 하단에 기존 `.tree` 그대로 렌더 — 이 phase 이전과 시각적으로 동일 |
| typing(디바운스 300ms 대기 중) | 아이콘·리스트 영역 모두 변화 없음(요청이 아직 발사되지 않았으므로) — 이전 상태(빈 트리 또는 이전 결과) 유지 |
| loading(요청 발사~응답 전) | 좌측 아이콘이 12px 스피너로 교체(기존 `.spinner` 패턴 축소판, `border-top-color: var(--accent)`) — 리스트 영역은 이전 내용을 유지한 채 깜빡임 없이 교체 대기(빈 화면으로 순간 초기화하지 않음) |

| no-results(0건) | `.searchResults`에 `.empty`와 동일 스타일의 중앙 정렬 텍스트: "'{query}'에 대한 검색 결과가 없어요"(Copywriting 참조) |
| result-hover | 행 배경 `var(--surface-2)`(트리 hover와 동일 관례), `cursor: pointer` |

| error(search fail) | `.searchResults` 영역에 `.empty`와 동일 배치, 색만 `var(--destructive)`: "검색하지 못했어요." + 인라인 텍스트 버튼 "다시 시도"(`SaveStatusBar`의 재시도 버튼과 동일 스타일 — 배경 없음, weight 600, hover underline) |
| 요청 경합(레이스) | 여러 debounce 요청이 겹칠 경우 **가장 최근에 발사한 요청의 응답만 반영**, 이전 요청의 늦은 응답은 무시(자동저장 seq 가드와 동일한 원칙의 검색판 — 옛 결과가 새 결과를 덮어쓰는 깜빡임 방지) |
| dark 테마 | 전부 `var(--token)` 참조, 신규 CSS 없음 |

> 잠긴 값(06-CONTEXT.md): 문서 컨텍스트 메뉴 ".md 내보내기", 폴더 컨텍스트 메뉴 ".zip 내보내기", VIEWER+. 컴포넌트는 기존 `FolderContextMenu` 그대로, 배열에 항목만 추가.

|------|-----|

| dark 테마 | 전부 `var(--token)` 참조, 신규 CSS 없음 |
