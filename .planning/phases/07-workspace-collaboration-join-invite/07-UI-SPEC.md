> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — shadcn 미도입 (Phase 1~6과 동일, `components.json` 부재로 재확인) |
| Preset | not applicable |
| Component library | none — 순수 CSS Modules + `src/app/globals.css`의 `docs/ui-kit.html` 이식 토큰. 새 팔레트·새 컴포넌트 라이브러리를 만들지 않는다 |
| Icon library | lucide-react (기존 설치, 추가 의존성 없음) |
| Font | IBM Plex Sans(UI 크롬 전부) |

**이 phase가 신규로 설계하는 표면:** 워크스페이스 멤버 페이지(`w/[wsId]/members` — 승인 대기 목록·멤버 목록·회원 초대 검색, `FolderTree` 신규 하단 nav 항목), 대시보드 "워크스페이스 참여 신청" 섹션(`DashboardPage` 신규 행), 초대 수락 결과 페이지(`/invitations/accept` — 5개 결과 상태를 갖는 신규 단독 라우트).

**재사용 원칙(재질문 대상 아님):** `Button`/`Input`/`ConfirmDialog`/`Card`의 기존 관례를 그대로 확장한다. Phase 6이 도입한 pill(`border-radius: 999px`, chip/read-only tag)과 검색 디바운스·레이스 가드·spinner 패턴(`SearchBox.tsx`)을 재사용하며, 이 phase는 그 위에 새 시각 값을 발명하지 않는다. 다크 테마는 Phase 5의 `[data-theme="dark"]` 12개 변수 오버라이드만으로 전부 자동 전환되므로(전 컴포넌트 `var(--token)` 참조), 이 phase가 새로 만드는 표면도 전부 토큰만 참조해 별도 다크 CSS를 추가하지 않는다.

## Layout & Composition Contract

| 규칙 | 내용 |
|------|------|
| 멤버 페이지 경로/셸 | `w/[wsId]/members/page.tsx` — `w/[wsId]/layout.tsx`의 `.main` 슬롯에 렌더(사이드바+본문 그리드 유지). `TrashList.module.css`의 `.wrap`(`height:100%; overflow-y:auto; padding: var(--space-xl)`)와 동일한 페이지 셸을 재사용 — 신규 셸 없음 |
| 멤버 페이지 진입점 | `FolderTree`의 하단 nav에 `휴지통` 링크(`trashLink`) 아래 새 행 `membersLink` 추가: `... → trashLink → membersLink(신규) → ThemeToggle`. 동일한 40px/`border-top`/hover(`--surface-2`)/active(`--accent-weak` 배경+`--accent` 텍스트) 관례를 그대로 확장(신규 스타일 없음), 아이콘만 lucide `Users` 16px로 교체 |
| 멤버 페이지 섹션 순서 | 제목("멤버") → **승인 대기 중**(ADMIN+ 전용, 실행이 필요한 항목이라 최상단) → **멤버 목록**(VIEWER+, 페이지의 주 콘텐츠) → **회원 초대**(ADMIN+ 전용, 가끔 쓰는 발견형 액션이라 최하단) |
| ADMIN 전용 섹션의 비-ADMIN 처리 | `TrashList`의 "버튼은 보이되 disabled+hint" 관례를 따르지 않고, **승인 대기 중·회원 초대 섹션 자체를 렌더하지 않는다.** 근거: Trash의 복원/삭제는 "모두가 보는 같은 항목에 대한 액션 게이팅"이지만, 여기 두 섹션은 VIEWER/EDITOR에게 어떤 정보 가치도 없는 ADMIN 전용 화면이라 빈 게이트를 보여주는 것 자체가 소음이다. 서버는 여전히 `requireRole(wsId, "ADMIN")`으로 실제 라우트를 방어한다(CLAUDE.md "UI 버튼 숨김은 보안이 아니다" — RSC가 `canManage` boolean만 클라이언트로 넘기는 것은 `TrashList`의 `canRestore`/`canPermanentDelete` boolean-전달 관례와 동일 원칙) |
| 대시보드 참여 신청 위치 | `DashboardPage`의 `.grid` **아래**에 새 섹션 삽입: `header → grid → joinSection(신규)`. 상단 1px `var(--border)` 구분선 + `margin-top: var(--space-xl)` `padding-top: var(--space-lg)`로 그리드와 분리 — 신규 CTA가 "워크스페이스 만들기"의 시각적 우위를 넘보지 않도록 보조 액션으로 하단 배치(Phase 1 Visual Hierarchy 원칙 계승) |
| 초대 수락 페이지 셸 | `(auth)/login/page.module.css`의 `.page`(`min-height:100vh; flex center; padding: var(--space-2xl) var(--space-md)`) + `Card` 컴포넌트(`max-width:360px`)를 그대로 재사용 — 로그인/가입과 동일한 "중앙 카드, 배경은 --bg 단색" 언어(Phase 1 Visual Hierarchy 계승), 신규 셸 없음 |
| 반응형 | 이 phase 범위 밖(Phase 1~6과 동일 — 데스크톱 폭 전제) |

## Color

Phase 1~6이 이식/확정한 토큰 그대로 재사용(재정의 없음, 신규 색상 없음). 라이트 기준 hex만 표기(다크는 `[data-theme="dark"]` 오버라이드가 자동 적용):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff`(`--bg`) | 멤버 페이지 배경, 초대 수락 카드 배경, 대시보드 배경 — 변경 없음 |
| Secondary (30%) | `#f8fafc`/`#eef2f6`/`#e5e7eb`(`--surface`/`--surface-2`/`--border`) | 멤버/요청 행 hover(`--surface-2`), 역할 배지 배경(`--surface-2`)+테두리(`--border`), 대시보드 참여 신청 섹션 상단 구분선(`--border`) |
| Accent (10%) | `#2563eb`(`--accent`) | 아래 "Accent reserved for" 목록에 한정 |
| Destructive | `#dc2626`(`--destructive`) | 거절 확인 버튼, 초대 발송 실패 텍스트, 초대 수락 실패 상태(만료/재사용/서명불일치/wrong-user) 아이콘·제목 |

**Accent reserved for (Phase 1~6 목록에 이 phase 항목만 추가):**
- (승계) 선택된 트리 노드, 열려있는 문서 노드, 각종 focus 아웃라인, 현재 위치 nav 강조(`trashLinkActive`류)
- **[신규]** 멤버 페이지 nav 링크(`membersLink`)의 현재 위치 강조 — `trashLinkActive`와 동일 관례(배경 `--accent-weak`, 텍스트 `--accent`)
- **[신규]** 회원 검색 입력 focus 시 하단 구분선, 로딩 스피너 `border-top-color` — `SearchBox`와 동일 관례
- **[신규]** 승인 버튼(`Button variant="primary"`) 배경, 초대 버튼(`Button variant="primary"`) 배경 — 둘 다 "긍정적 확정 액션" 1건씩만
- **[신규]** 초대 수락 성공 아이콘(`CheckCircle2`) — 성공 상태 1건 한정

**Accent를 쓰지 않는 것(명시):** 역할 배지(모든 역할이 동일 중립 스타일 — OWNER라고 강조하지 않는다, Phase 1 "활성 표시는 색이 아니라 굵기/명도" 원칙 계승), 멤버 목록 행 자체(hover만 `--surface-2`), "이미 멤버"/"초대 보냄" 배지(중립 정보, accent 아님), 거절 버튼(destructive 사용, accent 아님).
