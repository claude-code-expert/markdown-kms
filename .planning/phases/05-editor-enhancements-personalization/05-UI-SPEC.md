## Design System

| Property | Value |
|----------|-------|
| Tool | none — shadcn 미도입(Phase 1~4와 동일, 05-CONTEXT.md `shadcn_initialized: false`로 재확정) |
| Preset | not applicable |
| Component library | none — 순수 CSS Modules + `src/app/globals.css`의 `docs/ui-kit.html` 이식 토큰. 이 phase는 신규 팔레트를 만들지 않고 **기존 `:root` 토큰의 `[data-theme="dark"]` override**만 추가한다 |
| Icon library | lucide-react (기존 설치, 추가 의존성 없음) |
| Font | IBM Plex Sans(UI 크롬 전부) — IBM Plex Mono는 `EditorHost`(Phase 2 소유)가 그대로 유지, 이 phase가 건드리지 않음 |

**이 phase가 신규로 설계하는 표면:** 이미지 업로드 드롭존/에러 배너(에디터 내부), 툴바 pressed(`:active`)+300ms 지연 툴팁, 레이아웃 모드 토글(제목 입력 행 우측), 사이드바 하단 테마 토글 행, `EditorPreviewLayout`의 리사이즈 핸들 + 레이아웃 모드별 grid 변형, 크래시 복구 다이얼로그(`ConfirmDialog` 확장), 다크 테마 토큰 오버라이드 전체.

**재사용 원칙(재질문 대상 아님):** `ConfirmDialog`/`Modal`/`Button`/`SaveStatusBar`의 스피너·에러 텍스트·인라인 버튼 관례를 그대로 확장한다. 새 색상·새 컴포넌트 라이브러리를 발명하지 않는다. 다크 테마는 컴포넌트 코드를 바꾸는 게 아니라 **CSS 변수만 뒤집는다** — 기존 컴포넌트가 전부 `var(--token)`을 참조하므로 대부분은 이 phase가 손대지 않아도 자동으로 다크 전환된다. 예외 1건(툴바 툴팁 배경)은 아래 Toolbar Interaction Contract에서 명시.

## Layout & Composition Contract

| 규칙 | 내용 |
|------|------|
| 레이아웃 모드 토글 위치 | `DocumentWorkspace`의 기존 제목 입력 행(40px, 우측 컬럼 최상단)을 좌우로 나눈다: 좌측 `flex:1` 제목 `<input>`(기존 그대로) + 우측 고정폭 3버튼 세그먼트 컨트롤. **새 행을 추가하지 않는다** — split/editor-only/preview-only 전환은 렌더된 패널이 바뀌어도 항상 보여야 하므로(모드 전환 뒤로 갈 수 없는 상태 방지), 어떤 레이아웃 모드에서도 사라지지 않는 이 행에 둔다(05-CONTEXT.md "에디터 헤더/툴바 영역" 중 헤더 쪽으로 해석 — 툴바는 preview-only에서 숨는 표면이라 토글을 못 둔다) |
| 테마 토글 위치 | 사이드바 최하단, 기존 "휴지통" 고정 행(Phase 4, 40px) **바로 아래**에 동일 패턴의 새 40px 행 추가. 테마는 문서 단위가 아니라 세션 전체 설정이라 트리 스크롤 영역이나 툴바가 아니라 사이드바(모든 라우트에서 상시 노출)에 둔다(Claude's Discretion — 05-CONTEXT.md는 위치를 잠그지 않음) |
| `EditorPreviewLayout` grid 변형 | 기존 `grid-template-columns: minmax(0,1fr) minmax(0,1fr)` 고정 비율을 레이아웃 모드/리사이즈 상태에 따른 동적 값으로 교체: split=`{ratio}% minmax(0,1fr)`(기본 50/50, 리사이즈로 20~80% 사이 변경), editor-only=`1fr`(미리보기 패널·구분선 미렌더), preview-only=`1fr`(에디터 패널·툴바 미렌더, 미리보기만). 기존 `grid-template-areas`/`.editorPane`/`.previewPane` 클래스명은 유지, 값만 조건부 |
| 리사이즈 핸들 | split 모드에서만 렌더. `.editorPane`의 기존 `border-right: 1px solid var(--border)` 위치에 6px 폭의 투명 드래그 히트 영역을 겹쳐 배치(`position:absolute; right:-3px`). idle 시 시각적으로는 기존 1px 보더만 보임(신규 요소가 드러나지 않음) |
| 이미지 드롭존 오버레이 | `.editorPane` 내부 전체를 덮는 `position:absolute` 오버레이, 파일을 에디터 위로 드래그 중일 때만 렌더(그 외 DOM에 없음 — `display:none` 토글이 아니라 조건부 렌더로 리플로우 비용 없앰) |
| 업로드 에러 배너 | 툴바(44px) 바로 아래, 에디터 페인 내부 상단에 삽입되는 인라인 배너(새 행이 아니라 `EditorHost` 위에 조건부로 얹히는 오버레이형 배너 — 문서 높이를 밀어내지 않도록 `position:absolute`, 에디터 스크롤 영역과 별개) |
| 복구 다이얼로그 | `ConfirmDialog` 그대로 사용, `DocumentWorkspace` 마운트 시 `hasNewerDraft` prop이 true일 때만 `open`. 문서를 열자마자(자동저장 루프 시작 전) 판단 — RSC가 `draft.updated_at > document.updated_at`을 이미 계산해 prop으로 내려준다(구현 세부는 Claude's Discretion, CONTEXT §임시저장·크래시 복구) |
| 반응형 | 이 phase 범위 밖(Phase 1~4와 동일 — 데스크톱 폭 전제) |

## Color

### 라이트(기존 재사용, 재정의 없음)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` (`--bg`) | 변경 없음 |
| Secondary (30%) | `#f8fafc`/`#eef2f6`/`#e5e7eb` (`--surface`/`--surface-2`/`--border`) | 변경 없음 + 에러 배너 배경(`--surface-2`), 드롭존 오버레이 배경(`--surface` 반투명 없이 그대로) |
| Accent (10%) | `#2563eb` (`--accent`) | 아래 "Accent reserved for" 목록에 이 phase 항목 추가 |
| Destructive | `#dc2626` (`--destructive`) | 변경 없음 + 업로드 에러 텍스트, 복구 다이얼로그 "폐기" 버튼 |

**Accent reserved for (Phase 4 목록에 이 phase 항목만 추가):**
- (Phase 1~4 승계) 선택된 트리 노드, 유효 드롭 대상, 인라인 이름변경/버튼 focus, "저장 중" 스피너
- **[신규]** 이미지 드래그오버 시 드롭존 테두리(`2px dashed var(--accent)`)
- **[신규]** 리사이즈 핸들 드래그/hover 중의 2px 바
- **[신규]** 레이아웃 토글에서 현재 활성 모드 버튼(배경 `var(--accent-weak)`, 아이콘 `var(--accent)`) — 이것은 툴바의 "지속적 서식-활성 표시 금지" 규칙과 다른 범주다. 서식 버튼(볼드 등)은 "이 글자에 볼드가 적용돼 있는지" 추적을 금지한 것이고, 레이아웃 토글은 상호 배타적 3택 스위치(탭/세그먼트 컨트롤)로 "지금 어느 모드인지"를 보여주는 것이 이 UI 패턴의 본질적 기능이다(CONTEXT가 금지한 것과 다른 문제) |
| 복구 다이얼로그 "복원" 버튼 | `Button` `primary`(accent 배경, 기존 컴포넌트 그대로) |

저장 완료 상태가 accent를 쓰지 않는다는 Phase 4 원칙(anti-ai-slop, 과다 강조 방지)은 이 phase도 동일하게 유지 — 업로드 "완료" 상태도 별도 강조색 없이 placeholder가 실제 마크다운으로 조용히 치환되는 것 자체가 피드백이다(추가 토스트·색상 강조 없음).

**적용 방식:** `src/app/globals.css`의 `:root` 아래에 `[data-theme="dark"] { ... }` 블록을 추가해 위 12개 변수만 재선언한다. 기존 컴포넌트는 전부 `var(--token)` 참조이므로 이 블록 추가만으로 트리·휴지통·모달·버튼·상태 바가 전부 다크 전환된다 — 이 phase가 새로 만드는 표면(아래 섹션들) 외에는 CSS 수정이 필요 없다.

**알려진 예외(고쳐야 함):** `Toolbar.module.css`의 `.tooltip { background: var(--text); }`는 다크 모드에서 `--text`가 거의 흰색이 되어 흰 배경 위 흰 글자(`color:#fff`)로 툴팁이 보이지 않게 된다. 툴팁은 라이트/다크 어느 모드에서도 항상 어두운 말풍선이어야 하므로(테마 비종속 UI 요소), `var(--text)` 참조를 제거하고 고정값 `background: #0f172a;`로 바꾼다(새 토큰 추가 없이 하드코딩 — 이 하나의 용도로만 쓰이고 테마와 무관하게 값이 고정이라 변수화할 이유가 없다).

## Toolbar Interaction Contract (EDIT-10)

> `Toolbar.module.css` 상단 주석이 이미 이 phase로 defer한 두 가지: pressed 상태, 300ms 툴팁 지연. 둘 다 CSS만으로 구현(JS 상태 불필요) — 기존 `onMouseDown preventDefault`는 그대로 유지(포커스 유지 목적, 이 phase가 건드리지 않음).

| 상태 | 규칙 |
|------|------|
| default | 변경 없음 — `background: transparent` |
| hover | 변경 없음 — `background: var(--surface-2)` |
| pressed | `.button:active { background: var(--accent-weak); color: var(--accent); }` — 마우스 버튼을 누르고 있는 동안만(`:active`는 `preventDefault`와 무관하게 계속 동작), 뗀 순간 default/hover로 복귀. **버튼에 "이 서식이 지금 켜져 있다"를 추적하는 별도 클래스나 상태는 추가하지 않는다**(05-CONTEXT.md 명시 배제) |
| 툴팁 표시(hover 300ms 후) | 현재 `.buttonWrap:hover .tooltip { opacity: 1; }`은 즉시 전환된다. 아래처럼 "숨김은 즉시, 표시는 300ms 지연"으로 분리해야 한다 — 단일 `transition-delay`는 hover 해제 시에도 지연이 걸려 마우스를 뗐는데 툴팁이 잠깐 남는 버그가 생기므로 방향별로 나눈다:<br>`.tooltip { transition: opacity 0s linear 0s; }` (숨김 즉시)<br>`.buttonWrap:hover .tooltip { transition: opacity 0s linear 300ms; }` (표시 300ms 지연) |
| 툴팁 배경 | 위 Color 다크 섹션 "알려진 예외" 참조 — `var(--text)` 대신 고정 `#0f172a` |
