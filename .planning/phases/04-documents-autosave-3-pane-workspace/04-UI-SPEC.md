## Layout & Composition Contract

> 04-CONTEXT.md 잠금: 고정 3분할(사이드바 260px + 에디터|미리보기 1:1 + 하단 저장 상태 바), 리사이즈 없음. 라우트는 `w/[wsId]/layout.tsx`(사이드바 공유) + `d/[docId]/page.tsx`(문서). `EditorPreviewLayout` 내부(에디터·미리보기 그리드)는 건드리지 않는다 — 이 컴포넌트의 기존 주석이 이미 이렇게 예고하고 있다("Phase 4 wraps this with a tree sidebar + status bar without touching editor/preview internals").

| 규칙 | 내용 |
|------|------|
| 페이지 최상위 | `w/[wsId]/layout.tsx`가 Phase 3 `page.module.css`의 `.page`(height:100vh, `grid-template-columns: 260px minmax(0,1fr)`)를 그대로 승계한다 — 100vh 소유권이 `page.tsx`에서 `layout.tsx`로 옮겨갈 뿐, 값과 위치(트리 최상위 한 곳)는 동일. 좌측 = 사이드바(FolderTree 확장), 우측 = `{children}`(index 빈 상태 / `d/[docId]` 문서 워크스페이스 / `trash` 목록 중 하나). |
| 사이드바 폭 | 260px 고정 — Phase 3와 동일 값, 재질문 대상 아님. |
| 문서 워크스페이스 내부 구조(`d/[docId]`) | 우측 컬럼을 세로 3단으로 나눈다: ① 제목 입력 행(고정 높이 40px) ② 본문 행(`flex:1; min-height:0` — 그 안에 기존 `EditorPreviewLayout`을 그대로 얹는다, 내부 `grid-template-columns: 1fr 1fr` 무변경) ③ 저장 상태 바(고정 높이 40px). 세 행 모두 `EditorPreviewLayout`이 아니라 이를 감싸는 새 컴포넌트(가칭 `DocumentWorkspace`, 파일 배치는 Claude's Discretion)의 책임. |
| 상태 바 폭 | 사이드바를 제외한 우측 컬럼 전체 폭(에디터+미리보기 합산 폭과 동일) — 사이드바 아래까지 뻗지 않는다. 자동저장은 열린 문서 하나에 대한 상태이므로 사이드바와는 무관. |
| 문서 미열람 상태(`w/[wsId]` index) | 제목 입력·상태 바·`EditorPreviewLayout` 전부 렌더하지 않는다(저장할 대상이 없으므로). 우측 컬럼 전체를 채우는 중앙 정렬 빈 상태 플레이스홀더만 렌더(Copywriting Contract "Empty state" 참조). |
| 휴지통(`w/[wsId]/trash`) | 동일한 `layout.tsx`(사이드바 공유) 아래 우측 컬럼에 목록 뷰를 렌더. 제목 입력·상태 바는 없음(문서를 여는 화면이 아니므로). |
| 반응형 | 이 phase 범위 밖(Phase 1~3와 동일 — 데스크톱 폭 전제). |

## Spacing Scale

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | 사이드바 헤더 버튼 2개 사이 gap, 상태 바 아이콘-텍스트 gap |
| sm | 8px | 트리 노드 depth 0 좌측 padding, 상태 바/제목 입력 좌우 padding(단일 sm이 아니라 md 사용 — 아래 예외 참조) |
| md | 16px | 제목 입력 좌우 padding, 휴지통 목록 항목 padding, "완전삭제" 확인 다이얼로그 본문(기존 `ConfirmDialog` 재사용) |
| lg | 24px | 휴지통 목록 항목 아이콘-텍스트 gap 그룹 padding(재사용, 신규 값 아님) |
| xl | 32px | 휴지통 페이지 상단 여백(`page.module.css` `.main { padding: var(--space-xl) }` 재사용) |
| 2xl | 48px | (이 phase 미사용) |
| 3xl | 64px | (이 phase 미사용) |

Exceptions: 제목 입력 행·저장 상태 바 높이 40px는 사이드바 헤더(Phase 3, 40px)와 동일한 예외 취급 — "라벨 line-height + 상하 패딩"의 합성 값이나 구성 요소가 스케일 내부라 별도 예외로 보지 않는다. 그 외 신규 예외 없음.

## Typography

> Phase 1/2/3와 **동일한 UI 크롬 스케일을 재사용**한다(신규 발명 없음).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 13px | 400 (regular) | 1.5 |
| Label | 12px | 600 (semibold) | 1.4 |
| Heading | 16px | 600 (semibold) | 1.2 |
| Display | 20px | 600 (semibold) | 1.2 |

폰트 weight는 Phase 1/2/3와 동일하게 **400·600 2종만** 사용(700 미사용).

| 요소 | Role 매핑 |
|------|-----------|
| 문서 제목 입력 | Display(20/600) — 워크스페이스 이름(`page.module.css` `.title`)과 동일 급 재사용. 플레이스홀더 "제목 없음"은 같은 크기·weight, 색만 `var(--dim)` |
| 저장 상태 바 텍스트 | Body(13/400), 실패 시 색만 destructive로 전환(weight 변경 없음 — 2-weight 예산 준수) |
| 문서 트리 노드 라벨 | Body(13/400) — 폴더 노드와 동일(Phase 3 Tree Node Contract 승계) |
| "새 문서" 메뉴 항목 | Body(13/400) — 기존 컨텍스트 메뉴 항목과 동일 |
| 휴지통 항목 이름 | Body(13/400) |
| 휴지통 항목 삭제 시각 | Label(12/600) 대신 **Body 13px/400, `var(--muted)`** — 보조 정보라 라벨 강조(semibold)까지는 과함(anti-ai-slop, 불필요한 강조 방지) |
| 휴지통 빈 상태/복원 안내 배너 | Body(13/400) |
| 휴지통 페이지 타이틀 "휴지통" | Display(20/600) — `page.module.css` `.title`과 동일 위치·역할 |

## Color

Phase 1이 이식한 `src/app/globals.css` 토큰 그대로 재사용(재정의 없음, 신규 색상 없음):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` (`--bg`) | 문서 워크스페이스 배경, 상태 바 배경, 휴지통 배경 |
| Secondary (30%) | `#f8fafc`(`--surface`), `#eef2f6`(`--surface-2`), `#e5e7eb`(`--border`) | 트리 문서 노드 hover, 휴지통 항목 hover, 상태 바 상단 구분선, 제목 입력 하단 구분선(기본 상태) |
| Accent (10%) | `#2563eb`(`--accent`) | 아래 "Accent reserved for" 목록에 한정 |
| Destructive | `#dc2626`(`--destructive`) | 저장 실패 텍스트/아이콘, 문서 삭제·완전삭제 확인 다이얼로그, 완전삭제 버튼 |

**Accent reserved for (명시 목록 — Phase 3 목록에 이 phase 항목만 추가):**
- (Phase 3 승계) 선택된 트리 노드 배경/텍스트, 유효 드롭 대상, 인라인 이름변경 focus, "새 폴더" 버튼 focus
- **[신규]** 열려있는 문서의 트리 노드 배경 `var(--accent-weak)` + 텍스트 `var(--accent)`(현재 라우트의 `docId`와 일치하는 노드 — 폴더 "선택" 상태와 동일 시각 언어, "지금 보고 있는 문서"라는 의미로 자연 확장)
- **[신규]** 문서 제목 입력 필드 focus 아웃라인
- **[신규]** "새 문서" 헤더 버튼 focus 아웃라인
- **[신규]** 저장 상태 바의 "저장 중" 스피너 `border-top-color`(Phase 3 `.spinner` 패턴 그대로 재사용, 신규 값 아님)

저장 완료("저장됨") 상태는 accent나 신규 semantic color(녹색 등)를 쓰지 않는다 — `var(--muted)` 중립색만 사용한다. 근거: ui-kit 토큰에 success 계열 색이 없고, 저장은 매 1초마다 반복되는 일상적 상태라 매번 강조색을 켜면 화면이 소란스러워진다(anti-ai-slop, 과다 강조 방지). "실패"만 예외적으로 destructive를 쓴다 — 사용자가 반드시 인지해야 하는 유일한 상태이기 때문.

## Tree Node Contract — Phase 4 확장

> Phase 3의 `Tree Node Contract`(행 높이 32px·들여쓰기 8px+16px×N·hover/selected/pending/drag 스타일)를 문서 리프 노드에 **그대로** 적용한다. 아래는 문서 노드 전용 추가 규칙만 다룬다.

| 요소 | 값 |
|------|-----|
| 문서 아이콘 | lucide `FileText` 16px, `var(--muted)` — 폴더의 `Folder` 아이콘과 동일한 자리·크기·기본색 |
| 체브론 | 문서는 자식이 없으므로 항상 체브론 자리에 빈 공간(`chevronSpace`, 16px) — 폴더와 동일 정렬 유지 |
| 정렬 순서 | 같은 부모 아래에서 **폴더가 먼저, 문서가 나중**(각 그룹 내부는 서버가 내려주는 순서 그대로, 별도 정렬 UI 없음) — 탐색기류 앱의 통상 관례를 따른다(Claude's Discretion, 신규 요구사항 아님이라 최소 결정만) |
| 클릭 | 폴더처럼 토글 선택이 아니라 **`w/[wsId]/d/[docId]`로 즉시 이동**(Next.js `Link`) — 문서는 "선택"이 아니라 "열기"가 자연스러운 동작 |
| 현재 열람 중 표시 | 현재 라우트의 `docId`와 일치하는 문서 노드는 폴더 "선택" 상태와 동일한 시각(배경 `var(--accent-weak)`, 텍스트 `var(--accent)`, weight 600) — Color 섹션 Accent reserved 목록 참조 |
| 드래그 | 문서 노드는 `draggable` 아님 — 문서를 다른 폴더로 이동하는 기능은 04-CONTEXT.md에 언급이 없고 이 phase 성공 기준(DOC-01/02)에도 없다(범위 밖, YAGNI). Phase 3 폴더 DnD와 혼동되지 않도록 문서 행은 애초에 `draggable` 속성을 주지 않는다 — 드롭 대상으로는 여전히 동작할 필요 없음(폴더만 드롭 대상). |
| 컨텍스트 메뉴(우클릭/hover kebab) | 폴더의 4항목 메뉴와 별개로, 문서 노드는 **1항목 메뉴**: "삭제"(lucide `Trash2`, `var(--destructive)`). 이름 변경은 트리가 아니라 문서를 열어 상단 제목 입력에서 하므로 트리 메뉴에 넣지 않는다(중복 진입점 방지) |
| pending(삭제 진행 중) | Phase 3와 동일 — `opacity:0.5` + `pointer-events:none` + 12px 스피너 |

## Document Workspace Contract (`d/[docId]`)

### 제목 입력

| 요소 | 값 |
|------|-----|
| 위치 | 우측 컬럼 최상단, 사이드바를 제외한 전체 폭, 높이 40px |
| 스타일 | `<input>` 단일 행. 기본 상태: 테두리 없음, 배경 `var(--bg)`, 텍스트 Display(20/600). 하단 1px solid `var(--border)`(제목 입력 행과 본문 행을 시각적으로 분리 — 사이드바 헤더의 하단 구분선과 동일 관례). focus 시 하단 테두리만 `var(--accent)`로 전환(새 아웃라인을 추가하지 않고 기존 구분선 색만 바꿔 자리 이동 없이 강조) |
| padding | 좌우 16px(md), 상하 0(line-height로 세로 중앙 정렬) |
| placeholder | 값이 빈 문자열일 때만 "제목 없음" 표시, 색 `var(--dim)` — 실제 `document.title`이 빈 문자열로 남는 것은 허용(서버가 강제 필수값으로 만들지 않는 한, 이 phase는 클라이언트에서 제목 필수 검증을 추가하지 않는다 — 04-CONTEXT.md에 제목 필수 언급 없음) |
| 저장 연동 | 값 변경은 본문 변경과 동일한 자동저장 파이프라인을 탄다(1초 디바운스, 같은 payload의 `title` 필드) — 제목만을 위한 별도 저장 버튼·상태 없음 |

### 저장 상태 바

> EDIT-07 상태 전이: `저장 중` → 2xx `저장됨` / 실패 `저장 실패`+재시도. seq 가드는 순수 클라이언트 로직(어느 응답이 최신 발신 seq와 일치하는지 추적)이며 별도 시각 요소를 요구하지 않는다 — **stale 응답이 화면을 다시 "저장 중"이나 옛 "저장됨"으로 되돌리는 깜빡임이 절대 보이지 않아야 한다**는 것이 이 계약의 핵심(테스트로 검증할 동작이지 별도 UI가 아니다).

| 요소 | 값 |
|------|-----|
| 위치 | 우측 컬럼 최하단, 높이 40px, 상단 1px solid `var(--border)`, 배경 `var(--bg)` |
| 정렬 | 좌측 정렬 한 줄: [아이콘 14px] [gap 4px(xs)] [상태 텍스트] (실패 시 이어서 [gap 8px(sm)] [재시도 버튼]) |
| padding | 좌우 16px(md) |
| 저장 중 | 아이콘: Phase 3 `.spinner` 패턴 축소판(12px, `border-top-color: var(--accent)`) — 신규 스피너 발명 없음. 텍스트 "저장 중…" `var(--muted)` |
| 저장됨 | 아이콘: lucide `Check` 14px `var(--muted)`. 텍스트 "저장됨" `var(--muted)` — accent/녹색 없음(Color 섹션 근거) |
| 저장 실패 | 아이콘: lucide `AlertCircle` 14px `var(--destructive)`. 텍스트 "저장 실패" `var(--destructive)`. 이어서 인라인 텍스트 버튼 "재시도" — `<button>`, 배경 없음, 테두리 없음, 색 `var(--destructive)`, weight 600, hover 시 `text-decoration: underline`, padding 0(상태 바가 이미 40px로 컴팩트해 `Button` 컴포넌트의 8px×16px 패딩을 그대로 쓰면 바가 커져버린다 — 전용 인라인 스타일이 맞는 선택) |
| 초기 상태(문서를 막 열었을 때, 아직 아무 변경 없음) | "저장됨"과 동일 렌더(아이콘 Check, 텍스트 "저장됨") — 서버에서 막 로드한 `saved_seq` 시점 콘텐츠는 정의상 이미 저장된 상태이므로 별도의 "대기" 상태를 만들지 않는다 |
