<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → signup route | Untrusted email/password/name crosses into the server; password becomes a stored secret |
| browser → Auth.js authorize | Credential verification; error surface can leak account existence |
| browser ↔ session cookie | JWT session persisted client-side, resent on every request (AUTH-02) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Information Disclosure | authorize() login error | high | mitigate | Single generic outcome (return null) for both missing-user and wrong-password; UI copy "이메일 또는 비밀번호가 올바르지 않습니다." — never reveal which failed (ASVS V2). Unit-asserted. |
| T-02-02 | Tampering | JWT session cookie forgery/fixation | high | mitigate | Auth.js signs+encrypts the JWT with AUTH_SECRET (httpOnly/secure defaults, Pitfall 6); no hand-rolled cookie crypto (ASVS V3/V6) |
| T-02-03 | Denial of Service (data integrity) | Non-atomic signup → orphaned user with no membership | high | mitigate | Single db.transaction for user + EDITOR membership (Pattern 2); tests/auth/signup-atomicity.test.ts asserts rollback leaves no orphan (Pitfall 3) |
| T-02-04 | Elevation of Privilege (runtime) | bcrypt bundled for Edge → auth silently breaks / weak fallback | high | mitigate | export const runtime = "nodejs" on the signup route; bcrypt never called from middleware.ts (Pitfall 1) |
| T-02-05 | Spoofing | Password stored recoverably | high | mitigate | bcrypt cost-factor 10 hash (D-04); plaintext never persisted — asserted by tests/auth/signup.test.ts (ASVS V2/V6) |
| T-02-06 | Spoofing | Credential brute-force on login | high | transfer | Login rate-limit (in-memory counter) is implemented in Plan 04 where the login path is hardened; bcrypt cost factor slows offline attempts in the interim |
</threat_model>
