## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → mutating route | Every create/delete crosses into privileged server logic; role must be re-checked server-side |
| browser → login | Repeated attempts are an automation/brute-force surface |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Elevation of Privilege | A new mutating route missing a requireRole call | high | mitigate | requireRole is the single gate; the TDD matrix test (committed first) enumerates every Phase-1 route × 4 roles so a missing check fails a test, not ships (TRD §10, ASVS V4) |
| T-04-02 | Elevation of Privilege | Non-OWNER deletes a workspace | high | mitigate | DELETE handler calls requireRole(id, "OWNER") before any work; matrix asserts ADMIN/EDITOR/VIEWER → 403 (WS-02, D-15) |
| T-04-03 | Spoofing | Login credential brute-force | high | mitigate | In-memory 5-attempts/10-min limiter per email+IP; over-limit returns the generic failure (no lockout disclosure, O1); bcrypt cost factor compounds the cost (ASVS V2) |
| T-04-04 | Tampering | SQL injection via workspace name | medium | mitigate | Drizzle parameterized inserts; zod-validated, length-capped name; never string-concatenated into a raw sql template |
| T-04-05 | Information Disclosure | 403 vs 404 leaking workspace existence | low | accept | Both under-privileged and missing-workspace return a non-2xx without distinguishing content beyond the generic 403 copy; acceptable at ASVS L1 |
</threat_model>
